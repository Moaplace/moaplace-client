# UX 개선 설계: 1 Thing / 1 Page

> Issue: #5 — Toss UX 원칙 기반 전체 화면 UX 개선

---

## 문제

한번에 너무 많은 정보/입력이 보여 인지 부하가 높음.

- HomePage: 기능선택 + 이름 + 비번 + 캘린더 + CTA 한 화면 나열
- EntryModal: 닉네임 + 비번 동시 입력
- RoomPage: 지도 + 액션바 + 결과패널 동시 노출

## 적용 원칙

| 원칙 | 적용 |
|------|------|
| 포스텔의 법칙 (1 Thing / 1 Page) | 각 화면에 하나의 질문/입력만 |
| 힉의 법칙 | 선택지 최소화, 단계별 분리 |
| 밀러의 법칙 | 정보 청킹, 점진적 노출 |
| 폰 레스토프 효과 | 현재 스텝의 CTA만 강조 |

---

## 1. HomePage → 스텝 기반 위자드

같은 페이지에서 `step` 상태로 콘텐츠 애니메이션 전환.

**스텝 구성:**
1. 기능 선택 (모아장소 / 모아타임)
2. 모임 이름 입력 (건너뛰기 가능)
3. 비밀번호 설정 (건너뛰기 가능)
4. 날짜 선택 (모아타임만, 모아장소는 스킵)

**UX:**
- 상단 프로그레스 도트 (현재 스텝 하이라이트)
- 애니메이션: CSS transition (slide-left / fade)
- "다음" 버튼 + "건너뛰기" 텍스트 링크

## 2. EntryModal → 3단계 분리

기존 2단계(방비번 → 닉네임+비번)를 3단계로:
1. 방 비밀번호 (설정된 경우만)
2. 닉네임 입력
3. 개인 비밀번호 입력

각 스텝에 하나의 Input만.

## 3. RoomPage → 상태 기반 점진적 노출

- 마커 0개: 위치 찍기 버튼만 (공유 숨김, 결과패널 숨김)
- 마커 1개+: 위치 변경 + 공유 버튼 노출
- 마커 1개+: 결과 보기 트리거 노출

---

## 주요 결정

- 스텝 전환: 같은 페이지 내 애니메이션 (URL 변경 없음)
- 선택 필드(이름, 비번)에 "건너뛰기" 제공
- 모아장소 선택 시 캘린더 스텝 자동 스킵
- 프로그레스 도트로 현재 위치 인지
